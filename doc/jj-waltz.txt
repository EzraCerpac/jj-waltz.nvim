INTRODUCTION                                                   *jj-waltz-intro*

jj-waltz.nvim wraps the `jw` CLI from jj-waltz and exposes workspace actions
inside Neovim without extra runtime dependencies.

The plugin uses `jw switch --print-path` to mirror shell-driven switch
behavior. Switching adopts the starting tab and keeps a tab per visited
workspace root. Returning restores its splits, active window, cursor positions
and views. A first visit opens one window and maps the current clean file by
relative path, with the cursor clamped to fit the destination file.

Modified buffers stay in their original tab. Missing counterparts, unnamed or
special buffers, and files outside the source root start an empty tab instead.
Switching never forces a write, reload, rename or buffer deletion.

New workspace tabs use |:tcd| with the CLI destination, including its subdirectory
fallback. Existing tabs keep their cwd scopes (including |:lcd|); global cwd and
unrelated tabs are unchanged. A restored tab's cwd may differ from the CLI
destination. Commands use the active window's effective cwd.

Tabs are keyed by resolved root path, not workspace name or token. Renaming at
the same path reuses a tab; moving a workspace opens a new one. Removing a
workspace leaves its tab and buffers available for recovery; a failed switch
keeps the current tab. Reusing a root path reuses its tab. Closing a tab forgets
its context; switching back creates a fresh one. Context is session-local.
If a tab's active cwd no longer resolves to its associated workspace, the tab
is left intact and detached; switching back creates a fresh tab with the
correct workspace cwd.

==============================================================================
REQUIREMENTS                                             *jj-waltz-requirements*

- Neovim 0.10 or newer
- A `jw` binary with `links` subcommands and `switch --print-path`

Use jj-waltz 0.1.5 or newer, or a local build from the jj-waltz repo.

==============================================================================
SETUP                                                         *jj-waltz-setup*

Example with lazy.nvim:

>
  {
    "EzraCerpac/jj-waltz.nvim",
    main = "jj-waltz",
    cmd = {
      "JwPick",
      "JwSwitch",
      "JwCurrent",
      "JwRoot",
      "JwPath",
      "JwRemove",
      "JwRemoveKeepDir",
      "JwPrune",
      "JwLinksApply",
      "JwLinksRepair",
    },
    opts = {
      jw_cmd = "~/.local/bin/jw",
    },
    keys = {
      { "<leader>jw", "<cmd>JwPick<cr>", desc = "jj-waltz picker" },
    },
  }
<

==============================================================================
COMMANDS                                                   *jj-waltz-commands*

:JwPick
  Open the workspace picker.

:JwSwitch {name}
  Switch to or create a workspace and activate its editor tab.

:JwCurrent
  Show the current workspace name.

:JwRoot
  Show the current workspace root.

:JwPath {name}
  Show the resolved path for a workspace token or name.

:JwRemove [name]
  Forget a workspace. When {name} is omitted, `jw remove` defaults to the
  current workspace.

:JwRemoveKeepDir [name]
  Forget a workspace but keep its directory in place.

:JwPrune
  Forget missing workspaces.

:JwLinksApply
  Run `jw links apply`.

:JwLinksRepair
  Run `jw links repair`.

==============================================================================
CONFIGURATION                                         *jj-waltz-configuration*

`require("jj-waltz").setup({ opts })`

Supported options:

`jw_cmd`
  String executable path or argv table. Default: `"jw"`.

`picker`
  Picker backend. v0.1 uses `"vim_ui_select"`.

`switch_behavior`
  Default: `"retarget"`.

`open_strategy`
  Default: `"cwd"`.

`notify`
  Whether to surface command results through |vim.notify()|. Default: `true`.

`keymaps`
  When `true`, set a default `<leader>jw` picker mapping. Default: `false`.
